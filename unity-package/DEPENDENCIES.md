# Залежності форматів Unity package

Специфікація того, як пакет `com.silverechogames.forsaken-world-editor` будує залежності між файлами ігрових даних. Джерело правди — резолвери й парсери в `unity-package/Runtime` і імпортери в `unity-package/Editor`, не імена файлів поруч на диску.

Документ описує логіку пакета і замикання drag-and-drop. `GameDataDependencyGraph` збирає залежності, `GameDataDropImporter` імпортує їх пакетно, а `GameDataDragAndDrop` приймає файли у Project, Scene, Hierarchy і зоні drop у Game Data Browser після скану кореня. Файли можна тягнути з провідника або з рядків браузера. Результат зберігається в `Assets/ForsakenWorld/Imported`; Scene/Hierarchy додатково створює екземпляри префабів із підтримкою Undo.

Залежності завжди йдуть **назовні від файлу, який відкрили**. Зворотного пошуку («хто на мене посилається») пакет не робить. Кинутий `.stck` не підтягує `.smd`. Кинутий `.ski` не підтягує `.smd` і `.bon`.

## 1. Спільні правила резолву

Усі ігрові шляхи зводяться до відносного шляху від кореня даних (`GameDataIndex.Root`): `\` → `/`, без провідного `/`, без абсолютних шляхів і без виходу через `..` за корінь. Рядки в бінарних файлах — GBK (`GfxTextDecoder`). Індекс додатково матчить шляхи, де GBK-байти були прочитані як UTF-8 (`女` → `Ů`), і не перейменовує файли на диску.

`GameDataIndex.TryResolve` шукає так:

1. Точний відносний шлях (без урахування регістру).
2. Той самий шлях після відновлення CJK-аліаса.
3. Якщо дозволено suffix-match: унікальний файл, чий відносний шлях **закінчується** на `/" + запит`. Збіг лише за ім'ям файлу не достатній.
4. Якщо кандидатів більше одного — помилка `ambiguous`. Пакет не вибирає «перший ліпший».

Символічні посилання індекс пропускає. Розширення, яких немає в індексі, резолвер їх не побачить, навіть якщо файл лежить у корені даних.

### Що індексується

`.bmd` `.bon` `.dat` `.ecbsd` `.ecm` `.ecwld` `.gfx` `.ski` `.smd` `.stck` `.trn2` `.t2bk` `.t2mk` `.t2lm` `.wav` `.ogg` `.mp3` `.dds` `.bmp` `.tga` `.png` `.jpg` `.jpeg` `.xml`

### На що файли посилаються, але індекс цього не бачить

| Розширення | Хто посилається | Як шукається зараз |
| --- | --- | --- |
| `.gphy` | `.gfx` ID 220, сусід з тим самим ім'ям | обхід теки `.gfx` на диску, не індекс |
| `.spt` | `.ecwld` tree type | файл `.spt` не читається; імпорт шукає OBJ з тим самим ім'ям у `WorldTreeObjBuilder.TreesRoot` |
| `.phy` | `.smd` `PhysicsPath` | рядок зберігається, файл не резолвиться |
| `.tck` | `.smd` v8 `TrackCollectionPath` | це тека/маніфест треків, не файл анімації |
| `.stf` `.dcf` | AUI layout / string table | файлова система поруч з `interfaces/`, не індекс |
| `.ttf` | AUI `FontName` | `font/` або `resources/font/` на диску |
| `.sdr` | GFX `TexFile` | свідомо відхиляється як шейдер |
| `.fbx` | ECM `SkinModelPath` | не читається; шлях переписується на `.smd` |

Drag-and-drop має використовувати ті самі резолвери. Новий пошук «поруч у теці Unity-проєкту» або «будь-який файл з таким ім'ям» ламає правила Angelica і розходиться з уже імпортованими префабами.

### Класи залежностей

| Клас | Що робити при drop |
| --- | --- |
| Блокуюча | Без неї зібраний асет невалідний. Імпорт кореня зупиняється, залежність усе одно намагатися знайти й показати помилку. |
| М'яка | Імпорт кореня продовжується. Відсутність — warning, не помилка. |
| Записана, але не резолвиться | Шлях або лічильник є у файлі. Парсер його не розбирає. Drop не вигадує файл. |
| Лист | Вихідних файлових посилань немає. |

Цикли дозволені й мають обриватись за вже відвіданим відносним шляхом: `.gfx` ID 200 → інший `.gfx`; `.ecm` CoGfx → `.gfx` ID 230 → той самий `.ecm`.

## 2. Граф

```text
.ecm ──SkinModelPath──► .smd ──SkeletonPath──► .bon
  │                        │                      └── v5: треки всередині .bon (не файл)
  │                        ├──SkinPath / guess──► .ski ──texture name──► .dds/.tga/.bmp/.png/.jpg
  │                        │                      └── r_* ──► Textures/reflect/armorreflect.bmp
  │                        ├──v7+ action.TrackPath──► .stck
  │                        ├──PhysicsPath──► .phy          (не резолвиться)
  │                        ├──v8 TrackCollectionPath──► .tck   (тека треків, не файл)
  │                        └──HangerCount                  (тіло не читається)
  ├──AddiSkinPath──► .ski  (ті самі текстури)
  └──CoGfx FxFilePath──► .gfx
                              ├──TexFile──► gfx/textures/…
                              ├──ID 160 ModelPath──► .smd  (далі як вище)
                              ├──ID 170 Path──► sfx/ .wav/.ogg/.mp3
                              ├──ID 200 GfxPath──► .gfx
                              ├──ID 220 PhysDesc──► <gfx>.gphy   (не в індексі)
                              └──ID 230 ECMPath──► .ecm

.trn2 ──sub.Name──► .t2bk (обов'язково) + .t2mk (обов'язково) + .t2lm (м'яко)
   │                 └── texture table──► текстури землі
   ├──<map>.ecwld ──effects──► .gfx
   │              ├──models──► .ecm
   │              ├──sounds──► sfx/ .wav
   │              ├──trees──► .spt stem ──► OBJ у TreesRoot (інакше заглушка + warning)
   │              └── ornament/water/box offsets──► <map>.ecbsd
   │                     └── BSData\<n>.dat (вода; текстур у записі немає)
   └──litmodels/<map>/*.bmd ──mesh texture──► текстура (suffix-match)
         вода додатково──► textures/water/waternormal/water_normal00.dds

.xml (AUI) ──FileName──► surfaces/ або gfx/
            ├──DialogFile──► інший .xml
            ├──SoundEffect──► resources/…
            ├──.stf / .dcf поруч в interfaces/
            └──FontName──► font/*.ttf
```

## 3. Формати

### 3.1 `.smd` — маніфест скін-моделі

Сигнатура `MOXB` + `DMSA` (`MOXBDMSA`). Версії, які парсер приймає: **5, 6, 7, 8**. Інші відхиляються.

| Поле | v5 | v6 | v7 | v8 |
| --- | --- | --- | --- | --- |
| `SkeletonPath` | так | так | так | так |
| список `SkinPath` | так | так | так | так |
| `PhysicsPath` | так | так | так | так |
| `TrackCollectionPath` | порожньо | порожньо | синтетичне `tcks_<ім'я smd>` | рядок з файлу |
| кадри дії | з першого joint-запису (група, flags, joints) | `StartFrame` / `EndFrame` | те саме | те саме |
| `TrackPath` дії | немає | немає | є | є |
| hangers | лише лічильник | лише лічильник | лише лічильник | лише лічильник |

Резолвер: `ModelResourceResolver.Resolve(smd, smdRelativePath)`. База шляхів — тека самого `.smd`. Кожен запит шукається як `тека_smd + відносний шлях`, потім unique suffix самого запиту, потім unique suffix скомбінованого шляху. Неоднозначний suffix не перезаписується пізнішою спробою.

| Залежність | Клас | Правило |
| --- | --- | --- |
| `.bon` з `SkeletonPath` | блокуюча | без скелета модель не збирається |
| кожен непорожній `SkinPath` → `.ski` | м'яка | відсутній скін — warning, інші скіни лишаються |
| якщо список скінів порожній | м'яка | вгадування `<ім'я smd>.ski` у теці `.smd`. Якщо знайдено — warning, що скін узято не зі списку |
| `.stck` з `action.TrackPath` | м'яка, лише v7+ | база — тека треків, не завжди тека `.smd` (нижче) |
| анімація v5/v6 | не файл | треки беруться з `.bon` версії &lt; 6. Окремий `.stck` не шукається |
| `PhysicsPath` (`.phy`) | записана | рядок є, файл не резолвиться і не парситься |
| hangers | записана | якщо `HangerCount > 0` — warning «hangers are not supported yet». Тіло хангерів парсер не читає, тому drop не може підтягнути моделі зброї, доки парсер їх не розбере |

База `.stck` для v7+:

- якщо `TrackCollectionPath` містить теку — `тека_smd + ця тека`;
- інакше, якщо шлях не закінчується на `.tck` — `тека_smd + TrackCollectionPath` (саме так v7 отримує `tcks_<ім'я>`);
- інакше лишається тека `.smd`.

`TrackPath` дії резолвиться відносно цієї бази, не відносно теки `.smd` напряму.

**Drop `.smd` підтягує:** `.bon`, усі резолвнуті `.ski`, для v7+ усі резолвнуті `.stck`, потім текстури кожного `.ski` (розділ 3.3), включно з reflect-мапою, якщо вона потрібна. Для v5/v6 `.stck` не додається: анімація вже всередині `.bon` v5. Якщо `.smd` v5/v6, а `.bon` v6 — embedded-треків немає, це warning, не привід шукати `.stck` за ім'ям.

### 3.2 `.bon` — скелет

Сигнатура `MOXBEKSA`. Версії **5 і 6**.

| Версія | Зовнішні файли | Анімація |
| --- | --- | --- |
| 5 | немає | після кожного joint у файлі лежать position/rotation треки того самого формату, що `.stck` v1. Вони стають `EmbeddedTracks` |
| 6 | немає | треків у файлі немає. Анімація живе в `.stck`, на який посилається `.smd` v7+ |

`.bon` не називає ні `.smd`, ні `.ski`, ні `.stck`. Drop одного `.bon` нічого не підтягує. Імпорт як `BonAsset` зберігає кістки, joints, hooks і, для v5, embedded-треки.

Щоб зіграти кліп, `.stck` треба зіставити зі скелетом. Це робить лише `.smd`: індекс joint у треку — це індекс joint у `.bon`, не ім'я кістки. Вгадувати сусідній `.bon` за ім'ям `.stck` не можна.

### 3.3 `.ski` — скін

Сигнатура `MOXBIKSA`. Версії **8 і 9**. Morph, morph-skin, supple і muscle меші парсер відхиляє цілком: такий `.ski` не імпортується, навіть якщо текстури в ньому є.

| Версія | Палітра іменованих кісток | Прив'язка до скелета |
| --- | --- | --- |
| 8 | немає (`boneCount` у заголовку не читається як імена) | індекс кістки скіна = індекс кістки скелета |
| 9 | є, length-prefixed імена | ім'я шукається в `.bon`; відсутня кістка — warning, індекс −1 |

Текстура меша — це індекс у таблиці `TexturePaths`, не шлях у самому меші. Матеріал (ambient/diffuse/emissive/specular/power/two-sided) теж у файлі й окремого файлу не потребує.

Резолвер текстури: `SkiTextureResolver`. З шляху текстури береться **лише ім'я файлу**. Кандидати, по черзі, exact потім unique suffix:

1. `<тека ski>/Textures/<ім'я>`
2. `<тека ski>/Tex_<ім'я ski>/<ім'я>`
3. `<тека ski>/<ім'я>`

Приймаються розширення, які індексуються: `.dds` `.bmp` `.tga` `.png` `.jpg` `.jpeg`. `.dds` додатково читає DX9-заголовок (`DdsHeaderParser`): DXT1/3/5 і нестиснені; volume, неповні mip і екзотичні FourCC позначаються, але файл усе одно є залежністю. Unity 6000 імпортує DXT нативно, пакет не декодує DDS у `Texture2D` сам, якщо нативний імпорт проходить.

Якщо ім'я файлу текстури починається з `r_` (без урахування регістру), слот іде в шейдер Armor Reflect і тягне спільну сферу `Textures/reflect/armorreflect.bmp` (unique suffix дозволено). Це одна мапа на модель, не на кожен `r_`-файл.

**Drop `.ski` підтягує:** кожен непорожній запис `TexturePaths` і, якщо хоч один слот `r_`, `armorreflect.bmp`. `.bon` не підтягується: v8 взагалі не має імен, v9 має імена, але не шлях до скелета.

### 3.4 `.stck` — трек дії

Сигнатура `MOXBKCTS`. Єдина версія: **1**. Інші відхиляються.

Файл містить кількість треків, діапазон кадрів, FPS і для кожного joint індекс плюс канали position/rotation (keys + segments). Вихідних шляхів немає.

Drop `.stck` нічого не підтягує. Кліп має сенс лише як залежність `.smd` v7+ (або як embedded-трек `.bon` v5, який окремим файлом не є).

### 3.5 `.ecm` — обгортка моделі

Текстовий файл `ключ: значення`, кодування через `GfxTextDecoder`. Окремої версії немає. Якщо перші байти — `MOXB`, це бінарний ECM: парсер повертає помилку і нічого не резолвить.

Що читається і резолвиться (`EcmModelResolver`):

| Поле | Клас | Пошук |
| --- | --- | --- |
| `SkinModelPath` | блокуюча | має резолвитись у `.smd`. Кандидати: як записано; той самий шлях з `.smd`; якщо закінчується на `.fbx` — заміна розширення на `.smd`; саме ім'я файлу; ім'я файлу з `.smd`. Кожен — exact, потім unique suffix. Потім fallback: `<тека ecm>/<basename>.smd` **лише exact**. Якщо оригінальний шлях мав теки, а спрацював fallback — warning |
| `AddiSkinPath` | м'яка | `Models/<шлях>`, сирий шлях, `Models/<basename>.ski`, `<basename>.ski`. Має бути `.ski`. Неоднозначний suffix зупиняє пошук. Дубль уже наявного скіна `.smd` не додається |
| `FxFilePath` у секції CoGfx | м'яка | `.gfx`, далі весь граф GFX. `EventType` поза лімітом `CoGfxNum` і ключі після кінця секції CoGfx ігноруються |
| `CombineActName` / `BaseActName` | не файл | імена дій вже зібраного `.smd`, окремий файл не шукається |

Кінець секції CoGfx — перший з ключів `CombineActName`, `ECMHookCount`, `AddiSkinCount`, `ChildCount`, `ScriptCount`, `PhysFileName`. Самі `PhysFileName`, дочірні моделі, хуки ECM, скрипти й події всередині дій **не зберігаються**. Godot-імпортер теж їх ще не тягне. Drop не повинен вгадувати `.phy` або дочірній `.ecm` за сусіднім ім'ям.

**Drop `.ecm` підтягує:** `.smd` з `SkinModelPath`, додаткові `.ski`, потім усе, що тягне цей `.smd` (розділ 3.1), потім кожен CoGfx `.gfx` і їхні графи (розділ 3.6). CoGfx вішається на hook скелета за `HookName`; якщо хука немає — warning, GFX усе одно є залежністю файлу.

### 3.6 `.gfx` — ефект

Текстовий файл без бінарної версії. Заголовок — пари ключ/значення. Елементи мають `SystemId`. Невідомий ID не створює файлової залежності (візуал — stub), але якщо в його властивостях є відомі ключі нижче, drop все одно має їх прочитати: парсер зберігає сирі пари.

Пошук GFX з чужого файлу (`GfxSceneBuilder.TryResolveGfx`): як записано; `+.gfx`, якщо розширення немає; `gfx/<шлях>`; `gfx/<шлях>.gfx`; якщо шлях уже починається з `gfx/` — варіант без цього префікса. Exact, потім unique suffix.

| ID | Що це | Файлова залежність | Резолвер |
| --- | --- | --- | --- |
| 100, 101, 102 | sprite / decal | `TexFile` або `Tex File` | `GfxTextureResolver` |
| 110 | speed trail | те саме | те саме |
| 120–125 | particles | те саме | те саме |
| 130 | light | немає | — |
| 140, 190 | ring / paraboloid | `TexFile` | `GfxTextureResolver` |
| 150, 152 | lightning | `TexFile` / `Tex File` | те саме |
| 151 | lightning bolt | те саме | те саме |
| 160 | модель | `ModelPath` → `.smd` | `GfxModelResolver`, далі граф `.smd` |
| 170 | звук | `Path`, `Path_2`, … за `PathNum` | `GfxSoundResolver` |
| 180 | lightning trail | `TexFile` | `GfxTextureResolver` |
| 200 | вкладений ефект | `GfxPath` → `.gfx` | `TryResolveGfx`, рекурсивно |
| 210, 211 | grid | `TexFile` | `GfxTextureResolver` |
| 220 | phys emitter | `TexFile` + сусідній `.gphy` | текстура як вище; `.gphy` — файл `<ім'я gfx>.gphy` у тій самій теці, лише якщо заданий `PhysDesc` |
| 230 | ECModel | `ECMPath` → `.ecm` | exact + unique suffix, без префікса `gfx/`. Далі граф `.ecm`. `LDType` 1/2 (caster skin) окремого файлу не додає |

`GfxTextureResolver`, по черзі:

1. `gfx/textures/<шлях як записано>`
2. `gfx/textures/<ім'я файлу>`
3. сирий шлях
4. якщо немає розширення `.dds/.tga/.png/.jpg/.bmp` — ті самі кандидати з суфіксом `.dds`

`.sdr` не є текстурою і не підтягується.

`GfxModelResolver`: `gfx/Models/<шлях>`, `gfx/models/<шлях>`, сирий шлях; якщо немає `.smd` — ті самі з `.smd`; якщо в шляху є теки — ще `gfx/Models/<ім'я файлу>` і з `.smd`.

`GfxSoundResolver`: `sfx/<шлях>`, сирий шлях. Якщо немає `.wav/.ogg/.mp3` — кожне з цих розширень для `sfx/<шлях>`, сирого шляху і `sfx/<basename>`. Якщо шлях містить теки — ще `sfx/<ім'я файлу>`.

ID 170 може мати додатковий audio-event шлях (`UseCustom`, ключ після `PathNum`). Він резолвиться тим самим sound-резолвером, якщо непорожній.

**Drop `.gfx` підтягує:** усі текстури, `.smd` (і їхні графи), звуки, вкладені `.gfx`, `.ecm` (і їхні графи), і `.gphy`-сусіда для ID 220 з `PhysDesc`. `.sdr` пропускається з warning.

### 3.7 `.trn2` / `.t2bk` / `.t2mk` / `.t2lm` — терен

Це Loader B. Інший loader (не `1` у заголовку `.trn2`) відхиляється.

| Файл | Сигнатура | Версії | Роль |
| --- | --- | --- | --- |
| `.trn2` | `TRN2` (`0x54524E32`) | 1 | сітка, імена subterrain, таблиця текстур землі |
| `.t2bk` | `TBKB` (`0x54424B42`) | 1–6 | висоти й нормалі блоків. v2+ стискання; v&lt;5 прапор стискання нормалізується; v6 має flags блоку |
| `.t2mk` | `TMKB` (`0x544D4B42`) | 1–2 | маски шарів. v2 може бути zlib. Шар посилається на індекс текстури з `.trn2`, не на шлях |
| `.t2lm` | `T2LM` (`0x54324C4D`) | 1–2 | денні лайтмапи. v2 може бути DDS-блобом всередині, не окремим файлом |

Імена сусідів бере `.trn2`: для кожного sub `Name` у **тій самій теці**, що й `.trn2`, шукаються exact (без suffix):

- `<Name>.t2bk` — обов'язково для цього sub; відсутній sub пропускається з warning;
- `<Name>.t2mk` — так само;
- `<Name>.t2lm` — м'яка. Немає або бітий — ділянки без лайтмапи.

Текстури землі — рядки з таблиці `.trn2`. Спочатку exact `…/maps/<решта шляху карти>/<рядок текстури>` (префікс до `/maps/` включно зберігається, щоб не взяти текстуру іншого клієнта). Якщо немає — unique suffix всього рядка. Відсутня текстура замінюється magenta і лишається warning; для drop це все одно залежність, яку треба спробувати імпортувати.

**Drop одного `.trn2` (лише терен)** підтягує `.t2bk`, `.t2mk`, наявні `.t2lm` і текстури землі. Світових об'єктів він не містить.

**Drop карти** — це той самий `.trn2` плюс сусіди світу (розділ 3.8). Поточний map-імпорт уже робить це, коли поряд є `.ecwld`. Drag-and-drop карти має повторити `MapAssetImporter`, а не зупинятись на терені, якщо `<ім'я trn2>.ecwld` резолвиться.

### 3.8 `.ecwld` / `.ecbsd` / `BSData*.dat` — світ

`.ecwld`: сигнатура `ECWD` (`0x45435744`). Версії **12, 13, 14**. Інші відхиляються. Розмір звукового запису: v12 і v13 — 32 байти, v14 — 52. ECModel: v12 без `ShowType` (40 байт до рядків), v13+ — 44.

Сусід шукається як `<ім'я trn2>.ecwld` і `<ім'я trn2>.ecbsd` у тій самій теці (exact, потім файл поруч на диску без урахування регістру). Немає `.ecwld` — карта імпортується як терен і всі `.bmd` під `litmodels/<map>/`. Немає `.ecbsd` — вода відсутня, фільтр орнаментів не застосовується.

| Запис `.ecwld` | Залежність | Клас | Пошук |
| --- | --- | --- | --- |
| effect `Path` | `.gfx` | м'яка | шлях відносно `gfx\`, далі `TryResolveGfx` і граф GFX |
| model `Path` | `.ecm` | м'яка | шлях від кореня даних, exact + suffix, далі граф ECM. `Action` — ім'я дії, не файл |
| sound `Path` | `.wav` | м'яка | `sfx/<Path>`. На відміну від GFX, карта приймає **лише `.wav`** |
| tree type | `.spt` | м'яка | два AString на тип; перший — шлях `.spt`, другий (composite map) не використовується. Сам `.spt` не в індексі і не парситься. Імпорт мапи бере ім'я файла і шукає `<ім'я>_Branch/_Fronds/_Leaves.obj` під `WorldTreeObjBuilder.TreesRoot` (`B:\Git\PW146RUUnpackedAssets\trees`, рекурсивно). Немає OBJ — текстова заглушка і одне попередження на шлях |
| ornament ref | offset у `.ecbsd` | блокуюча для фільтра будівель | не шлях, а зсув |
| water ref | offset у `.ecbsd` → `BSData` | м'яка | немає води, якщо `.dat` не знайдено |
| box ref | світло в `.ecbsd` | немає файлу | кольори й напрям у самому `.ecbsd` |
| grass refs | `.mox` + бітмапа | м'яка | тип у заголовку `.ecwld` (`dwGrassOff`), запис `ECBSDFILEGRASS7` у `.ecbsd`, біти в `BSData` (zlib-чанк, як вода). Меш — `.mox`, текстура `Textures/` поруч. Висота з `.trn2` |

`.ecbsd`: обгортка `MOXB` + `BSDF` (`0x42534446`). Окремої версії файлу пакет не перевіряє; коротший або без магії файл дає warning і порожній документ. Орнамент містить шлях **відносно** `litmodels/<map>/`. Будівля — це `.bmd` під `litmodels/<map>/`, чий хвіст збігається з цим шляхом або з `<ім'я>.bmd`.

Для окремого drop `.ecbsd` зсуви орнаментів і води читаються з парного `.ecwld` лише як метадані, без обходу його ефектів і терену. Без цього файла доступна тільки таблиця імен `BSData`; імпортер повідомляє про відсутні зсуви, а не вгадує будівлі.

Вода: з таблиці імен `BSData` береться файл поруч з `.ecbsd` (шлях з імені, часто `BSData\<n>.dat`), інакше exact/suffix в індексі. Запис води має версію: нижче `0x10002000` відхиляється. `0x10003000` — мінорна версія, яку парсер розрізняє. У записі води немає шляху текстури. Єдина файлова залежність води — фіксована нормаль `textures/water/waternormal/water_normal00.dds` (unique suffix).

**Drop `.ecwld`** сам по собі не знає карти: ім'я `.trn2` і `.ecbsd` беруться з імені файлу в тій самій теці (`<basename>.trn2`, `<basename>.ecbsd`). Якщо їх немає — імпортуються лише ті об'єкти `.ecwld`, які резолвляться без терену (GFX, ECM, wav), плюс `.spt` лишаються нерезолвнутими. **Drop `.trn2` за наявності однойменного `.ecwld`** — повна карта: терен, `.ecbsd`, `BSData*.dat`, відфільтровані `.bmd` і їхні текстури, GFX, ECM, wav, нормаль води.

### 3.9 `.bmd` — будівля (LitModel)

Сигнатура `MOXB`. Далі або одразу версія LitModel, або прапор `0x80000001` (collide-only) і потім версія.

| Рівень | Підтримувані значення |
| --- | --- |
| LitModel | `0x10000001`, `0x10000002` |
| mesh | `0x10000002` … `0x10000006`, `0x10000100` (lightmap UV пропускаються) |

Текстура меша — фіксоване GBK-поле 256 байт, не індекс. `BuildingAssetImporter` резолвить його одним `TryResolve(..., allowUniqueSuffixMatch: true)`: спочатку exact, потім унікальний suffix. Немає текстури — матеріал без альбедо, warning. Окремих normal/specular файлів `.bmd` не називає. Two-sided є лише в mesh ≥ `0x10000005` і лежить у матеріалі, не у файлі. Хвостові collision-дані не читаються і залежностей не дають.

**Drop `.bmd` підтягує** лише ці текстури.

### 3.10 Текстури і звук

Листи. Drop не йде вгору до `.ski` / `.gfx` / `.bmd`.

| Формат | Версія / обмеження | Хто тягне |
| --- | --- | --- |
| `.dds` | DX9 `DDS ` + header size 124. DXT1/3/5, нестиснені RGB/RGBA. DXT3/5 на непрозорому SKI-слоті вмикають alpha clip 84/255 | SKI, GFX, BMD, терен, вода |
| `.bmp` `.tga` `.png` `.jpg` `.jpeg` | без версії пакета | ті самі, плюс AUI surfaces (`.tga` типовий) |
| `.wav` | карта — тільки він; GFX і AUI — один з трьох | ECWLD, GFX 170, AUI `SoundEffect` |
| `.ogg` `.mp3` | GFX і AUI, не карта | GFX 170 |

AUI-звук шукається як `resources/<шлях>`, потім сирий шлях від кореня даних. Це не `sfx/`.

### 3.11 AUI: `.xml`, `.dcf`, `.stf`

Окремої бінарної версії немає. Діалог — Angelica XML. Мова береться з теки, де є `interfaces/`: `<мова>/interfaces` або `resources/<мова>/interfaces`.

| Посилання | Куди | Клас |
| --- | --- | --- |
| `Resource/FrameImage` і дочірні `Resource`, ім'я яких **не** починається з `Gfx` | `FileName` → `surfaces/` мови, інакше `resources/surfaces/` | м'яка, текстура UI |
| `Resource`, ім'я починається з `Gfx` | `FileName` → `resources/gfx/`, інакше `gfx/`, далі граф `.gfx` | м'яка |
| `SUBDIALOG` `DialogFile` | інший `.xml` в `interfaces/`, рекурсивно | м'яка |
| `SoundEffect`, `SoundEffectClose` | `AngelicaUi.Sound`: `resources/<шлях>`, потім від кореня | м'яка |
| `.dcf` layout (`1gameui`, `2gameui`, `gameui`, `loginui`, `loadingui`) | токени `файл x y show` → `.xml` в `interfaces/` | м'яка. Сам `.dcf` не в індексі |
| `.stf` | таблиця рядків, не файл-асет. Ім'я: як задано, або `+.stf` | не графічна залежність |
| `FontName` | фіксована мапа: `方正细黑一简体` → `fzxh1jw.ttf`, `方正隶二简体` → `fzl2jw.ttf`, `方正隶变简体` → `fzlbjw.ttf`, `方正兰亭黑体` → `fzlthk.ttf`. Невідоме обличчя → `fzxh1jw.ttf`. Шлях: `font/<файл>`, інакше `resources/font/<файл>` | м'яка. `.ttf` не в індексі |

Пошук AUI — обхід файлової системи (`AngelicaUi`), не `GameDataIndex`. Drop `.xml` має повторити це, інакше surfaces і шрифти не знайдуться: їх немає в індексі, а `.xml` в індексі є.

`.dcf` drop підтягує перелічені `.xml` і їхні графи. `.stf` вихідних файлів не має.

## 4. Замикання для drag-and-drop

Кидання файлу в Unity має зібрати той самий граф, який уже будують резолвери, і імпортувати кожен унікальний файл один раз. Корінь даних — уже просканований `GameDataIndex`, не тека Unity-проєкту і не «файли поруч із кинутим асетом», якщо вони не входять у корінь.

| Кинули | Блокуюче | Підтягнути далі | Не підтягувати |
| --- | --- | --- | --- |
| `.smd` | `.bon` | `.ski` (або вгаданий однойменний), `.stck` лише v7+, текстури скінів, `armorreflect.bmp` якщо є `r_` | `.phy`, hangers, чужі `.smd` |
| `.ski` | — | текстури за трьома кандидатами, reflect-мапа якщо `r_` | `.bon`, `.smd`, `.stck` |
| `.bon` | — | нічого. v5 уже містить треки | сусідні `.stck` / `.ski` за ім'ям |
| `.stck` | — | нічого | скелет «з тієї ж теки» |
| `.ecm` | `.smd` з `SkinModelPath` | AddiSkin `.ski`, граф `.smd`, CoGfx `.gfx` і їхні графи | `PhysFileName`, діти, події дій |
| `.gfx` | — | текстури, `.smd`, звуки, вкладені `.gfx`, `.ecm`, `.gphy` сусіда для ID 220 | `.sdr` |
| `.trn2` | `.t2bk` і `.t2mk` кожного читабельного sub | `.t2lm`, текстури землі; якщо є однойменний `.ecwld` — повна карта, включно з травою (`.mox` + біти) | усі `.bmd` клієнта поза `litmodels/<map>/` |
| `.ecwld` | — | однойменні `.trn2` і `.ecbsd` якщо є; GFX/ECM/wav і трава (типи + `.mox` + біти з `.ecbsd`) | `.spt` як меш |
| `.ecbsd` | — | `BSData*.dat` з таблиці імен, `.bmd` за шляхами орнаментів відносно `litmodels/<ім'я файлу>/`, текстури цих `.bmd` | терен, якщо немає парного `.trn2` |
| `.bmd` | — | текстури мешів | інші будівлі карти |
| `.dds` і інші текстури, `.wav/.ogg/.mp3` | — | нічого | моделі, які їх використовують |
| `.xml` | — | surfaces, GFX-ресурси, `DialogFile`, звуки, `.ttf` за `FontName` | зворотні діалоги, які включають цей файл |
| `.dcf` | — | перелічені `.xml` і їхні графи | — |
| `.t2bk` `.t2mk` `.t2lm` `.dat` `.stf` | — | нічого. Це залежності, не корені | батьківський `.trn2` / `.ecbsd` за ім'ям |

Порядок імпорту всередині графа: листи (текстури, звук, `.gphy`, шрифти) → `.bon` / `.stck` / `.ski` → `.smd` → `.ecm` / `.bmd` / `.gfx` → терен → карта. Цикл обривається за відвіданим відносним шляхом; повторний CoGfx на той самий `.gfx` не імпортується вдруге.

Неоднозначний suffix — не вибір навмання, а помилка цієї гілки. Блокуюча неоднозначність (скелет `.smd`, `SkinModelPath`) зупиняє збірку цього кореня. М'яка (скін, текстура, GFX на карті) пропускає гілку і пише warning.

Відсутній файл у м'якій гілці не створює порожній Unity-асет-заглушку. Виняток, який вже є в імпортерах і його не треба дублювати новим способом: вода без нормалі й терен без однієї текстури землі все одно збираються, з warning.

## 5. Що свідомо не входить у граф

Це не прогалини drop-імпортера. Парсер шлях не віддає, тож підтягувати нічого.

- Hangers у `.smd`: відомий лише лічильник.
- `.phy` і вміст `.tck` як файли анімації. `.tck` у v8 — рядок теки колекції; самі кліпи — `.stck` у діях.
- Дочірні моделі ECM, `PhysFileName`, ECM hooks як окремі файли, скрипти, GFX/звук у подіях дій.
- Бінарний `MOXB` ECM.
- `.ski` з morph / supple / muscle.
- `.sdr`, на який показує `TexFile`.
- `.spt` дерева і друга AString-мапа типу дерева.
- Critters і bezier у `.ecwld`. Трава вже в графі: тип і `.mox` з заголовка `.ecwld`, біти з `.ecbsd` / `BSData`.
- Collision-хвіст `.bmd`, нічні vertex color, lightmap UV mesh `0x10000100`.
- Зворотні посилання: хто використовує цей `.ski` / `.stck` / текстуру.

Коли парсер почне читати hangers або дочірні ECM, граф drop має розширитись тими ж правилами, а не окремим пошуком за ім'ям.
