Ziel: Dasselbe Godot-Projekt läuft als Client und (headless) als Server. Der Server hat eigene
Spiellogik; der Forsaken-World-Server v773 (VM) dient nur als Datenquelle, vor allem für die
Positionen von NPCs und Monstern. Das Netzprotokoll des Original-Servers wird nicht nachgebaut
(viel Aufwand, kaum Nutzen).


------------------------------------------------------------------------------------------
0. DATEN, DIE SCHON DA SIND (Client)
------------------------------------------------------------------------------------------
data\elements.data      Vorlagen aller Gegenstände, NPCs, Monster, Fertigkeiten ...
                        (daraus ElementsV1.db: Namen DE / FR / EN)
data\aipolicy.data      KI-Verhalten der Monster
data\path.data          Wege (Patrouillen, Begleit-Quests)
data\dyn_tasks.data     dynamische Quests; Quest-Texte in script\*.lua je Sprache
data\<map>.dat          Ortsnamen je Map ("MOXB", z.B. "Port Liberté")
maps\<map>\precinct.clt Gebiete mit Namen, Wiederbelebungspunkten, Musik (Text)
maps\<map>\region.clt   Regionen (Schutzzonen, Sonderregeln)
maps\<map>\movemaps\    Wegfindungskarten (.hmap, pfmap.cfg, pf.mlu)
maps\<map>\flyareas.data, <map>.cld   Flugbereiche, Kollision
ElementsV1.db           SQLite (Plugin sqlite3.gd), Tabellen Elements_*, Pfadlisten

Was fehlt: wo NPCs und Monster stehen, wie oft sie neu erscheinen -> nur auf dem Server.


------------------------------------------------------------------------------------------
1. SERVER-VM AUSLESEN
------------------------------------------------------------------------------------------
[ ] (A) .vdi in Angelica_source/Server/ entpacken und nur lesend einhängen
        (qemu-img convert -O raw ... ; Partition mit losetup / mount -o ro, oder 7z x).
[ ] (A) Spielserver-Ordner finden (gamed u.ä.) und die Daten je Welt / Map auflisten:
        Spawn-Dateien (bei Angelica-Servern npcgen.data), Server-elements.data, Quests,
        Drop-Tabellen, Server-Kopien von movemaps / region.
[ ] (A) Versionen abgleichen: Server 773 gegen die Client-Daten (elements.data, Maps).
[ ] (B) Konfigurationen (Welt-Nummern <-> Map-Namen s1, s2, ...; Respawn-Zeiten).


------------------------------------------------------------------------------------------
2. SPAWNS IN DIE MAPS (Editor)
------------------------------------------------------------------------------------------
[ ] (A) Reader für die Spawn-Dateien (angelica_spawns.gd): je Eintrag Vorlagen-ID, Position,
        Richtung, Anzahl, Streuradius, Respawn-Zeit, Pfad, Tag / Nacht.
[ ] (A) Beim Map-Import Knoten "Spawns" mit Markern (NPC / Monster getrennt), Name aus
        ElementsV1.db in der gewählten Sprache, Modell aus elements.data (ECM) als Vorschau.
[ ] (B) Gebiete (precinct.clt) und Regionen (region.clt) als Bereiche in der Map.
[ ] (B) Wege (path.data) als Path3D.
[ ] (C) Marker im Editor bearbeiten und als eigene Spawn-Tabelle speichern.


------------------------------------------------------------------------------------------
3. GODOT-SERVER (headless)
------------------------------------------------------------------------------------------
[ ] (A) Start als Server: Export mit Feature "dedicated_server" bzw. --headless; Autoload
        GameServer (Server) / GameClient (Client), gleicher Code für Daten und Regeln.
[ ] (A) Netz: Godot-Multiplayer über ENet (UDP), Server entscheidet alles (Positionen,
        Treffer, Beute); Client sendet nur Eingaben.
[ ] (A) Welt-Instanzen je Map, Spieler sehen nur Objekte in ihrer Nähe (Interessens-Radius
        wie Load_Radius der Map-Objekte).
[ ] (A) Spawn-Verwaltung aus Teil 2: Erscheinen, Tod, Respawn-Timer.
[ ] (B) Bewegung und Wegfindung: movemaps lesen oder NavigationMesh aus Terrain + Gebäuden;
        Kollision (Terrain, .bmd, .cld) - siehe GFX-ECM-Todo-List "Kollision".
[ ] (B) Monster-KI aus aipolicy.data (erst einfach: angreifen, verfolgen, zurücklaufen).
[ ] (B) Speicher: SQLite (Konten, Figuren, Inventar, Quests); Vorlagen nur lesend aus
        ElementsV1.db / elements.data.
[ ] (C) Kampf, Fertigkeiten, Quests (dyn_tasks + Lua-Skripte), Handel, Chat.
[ ] (C) Mehrere Server-Prozesse (Login / Welt) erst bei Bedarf.
