# План перенесення редактора Forsaken World на Unity

> **Стан на 2026-11-03:** Unity UPM package для Unity 2022.3 із браузером ресурсів і частковим читанням GFX/ECM/SMD v8/BON v6/SKI v9/STCK v1 плюс Runtime STCK evaluation / AnimationClip assembly. Остання standalone-перевірка скомпілювала Runtime/Editor проти тимчасових Unity API stubs і пройшла 49 тестових випадків; real-asset scan на PW-Workshop Models-Database (models . pck) через той самий harness: SMD v8 1403 OK / 2144 unsupported (v5/v6), BON v6 5721 OK / 2214 unsupported (v5), SKI v9 12751 OK / 7562 unsupported (переважно v8), STCK v1 51240 OK / 0 fail; assembly SMD→BON/SKI 1401 OK / 1 missing skeleton / 0 assembler bugs; анімації SMD-actions→STCK: actions_ok=44276 / actions_fail=0 / skip_no_track=80, stck_tracks_eval_ok=1224040 / fail=0, clips_ok=44276 / fail=0 (без коміту ігрових ассетів). Це не запуск Unity Test Runner; реальна AssetDatabase/UI-інтеграція не перевірена. Загального відсотка не вказуємо: функціональні області мають різний масштаб.

## Межі та вихідні припущення

- Поточний репозиторій містить Godot-плагін редактора, а не готову гру: він читає зовнішні розпаковані дані Forsaken World з `.resources` і створює сцени/ресурси для редагування та перегляду.
- Переносимо насамперед можливості редактора й перегляду контенту. Це не план переносу сервера, мережевої гри або ігрової логіки.
- Цільова архітектура: C#-пакет/Editor assembly для Unity, окреме ядро читання форматів без залежності від Unity Editor API, а також Unity-компоненти для відтворення ефектів і сцен.
- Мінімальна версія пакета зараз Unity 2022.3; render pipeline та підтримувані платформи ще не визначені, тому не починати залежну від pipeline реалізацію шейдерів до окремого рішення. Оригінальні ігрові дані не додаються до репозиторію; тести мають використовувати створені мінімальні fixtures або дані, на які є дозвіл.

## Що вже робить Godot-плагін

- Імпортує текстові `.gfx` (UTF-8/GBK), розбирає заголовки, елементи, контролери, keypoints і масиви параметрів; будує дерево вузлів і повідомляє про невідомі ID.
- Створює та відтворює GFX з бібліотеки або з ігрових даних, зокрема вкладені GFX-контейнери, часові криві, альфу, матеріали та ефекти. Наявні builders для ID 100, 101, 110, 120–125, 130, 140, 150–152, 160, 170, 180, 190, 200, 210, 211, 220 і 230. ID 102 пропускається.
- Має панель GFX Player для запуску, зупинки та перемотування ефектів у відкритій сцені.
- Індексує `.ecm`, `.gfx` і `.trn2` у вибраному каталозі ігрових даних, підтримує пошук/фільтр і кеш списку, імпортує вибрані файли у сцени.
- Читає `.smd`, `.bon`, `.ski` та `.stck`, створює скелети, skinned meshes, матеріали/текстури DDS і анімації. З `.ecm` читає модель, додаткові скіни, CoGfx на кістках і базові зв'язки анімацій.
- Імпортує мапу `.trn2`: terrain, зазначені мапою будівлі, воду, ефекти, ECModel, звуки, освітлення, зміну день/ніч і радіус завантаження об'єктів.
- Читає XML-інтерфейси AUI, таблиці тексту та ресурси кількома мовами; будує попередній перегляд діалогів і основних типів контролів.
- Робить імпорт пакетів GFX з папки та додає створені вузли до відкритої сцени з підтримкою undo/redo.

## Відомі прогалини, які потрібно врахувати в оцінці

- GFX ID 102 відсутній; деякі параметри/рендер можуть відрізнятися між Vulkan і OpenGL.
- `.sdr`-текстури не підтримуються; GFX sounds і деякі моделі ще шукаються у старих output-каталогах; для деяких файлових наборів є відсутні ресурси.
- `.smd` версій 5/6, бінарні `.ecm`, події анімацій і дочірні моделі не підтримуються; частина CoGfx-параметрів, Hanger та Morph/Supple/Muscle meshes відсутні.
- Для мап ще потрібні колізії, skybox, частина fog/light/grass, вода з хвилями/відбиттями та інші другорядні елементи.
- Для AUI ще потрібні runtime-команди/анімації, `.dcf`-позиціонування, додаткові параметри layout, деякі стилі, GFX та Lua.
- Прогалини базуються на README і поточному `gfx_importer/GFX-ECM-Todo-List.txt`; перед плануванням релізу звірити їх із фактичним станом Godot-гілки.
